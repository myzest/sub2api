- 多窗口/在途场景：另一个页面刷新后应释放旧选择；清空前已进入诊断的请求可以完成，但不应重新回到列表；后续新请求正常记录。界面显示清空时间、实例和短诊断 ID，便于关联。

## 0.1.5 源码审查修复

沿插件请求、宿主错误调度、图片上传、工具 KV 回放、配置保存及 UI 状态查询检查本次全部变更。以下结论来自可达代码路径的静态分析，未声称实机复现或测试通过。

- 附件非 2xx 的错误体超过 64 KiB 或读取中断时，原先会丢失已收到的状态并变成传输错误；现保留 HTTP 状态，只省略不可用的诊断正文。
- 附件错误原先未传 Retry-After、限流及 request ID 响应头，影响宿主限流处理；现复用 Responses 转发的响应头白名单。
- 同图在途上传原先使用首个请求的取消上下文，会连带失败其他等待者；现独立上传，仅复用成功后的缓存，同键并发写入更新同一 LRU 条目。
- 既有 KV 回放用 float64 解码未知数值，可能损失大于 2^53 的整数精度；现使用 UseNumber，保留长度和尾部检查。
- 既有 UI 轮询一次失败后停止更新；现失败后继续只读轮询，恢复连接时补充账号选项并清除过期错误提示，页面关闭停止，不重发探测。
- 既有 UI 状态响应可乱序覆盖新探测并清除计时器；现状态查询串行执行。
- 既有账号刷新使用旧窗口配置，可能覆盖其他窗口已保存的路由；现刷新前加载最新配置并提示变化，保留本地脏表单。宿主缺少原子条件保存接口，真正同时保存的竞争仍需避免。

升级复用原发布者公钥：停用旧版、导入 0.1.15、启用并检查账号路由与新实例号。已保存的模型列表继续保留。识图传输字段默认 attachment，passthrough 可用于关闭图片回退进行对照；它不改变生图/改图接口的传输格式。旧产物保留，新包使用独立版本号。插件升级不会自动修改服务器主程序或各设备的 Codex 配置。
