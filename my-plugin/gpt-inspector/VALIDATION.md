## 已验证

- 独立 Go 模块编译、`go vet`、Go 测试和 race detector。
- 真实插件可执行文件的 go-plugin 握手、身份/版本校验、HostService v2 broker 回连、
  状态读取与 HTTP 转发。这里的宿主服务和上游均为可控测试夹具。
- 按账号读取模型与 Codex 推理档位；空默认值与显式 `none` 不混淆。
- 2 题 × 2 轮确实发送 4 次请求，并发数为 2，同一题各轮不会重叠；每次唯一会话 ID 与缓存键，
  单条独立输入、无历史、无工具。取消提交请求不会取消后台任务。
- 3 题 × 2 轮时，阻塞鹈鹕生成，另外两道文字题仍完成全部 4 条回答，且可在批次结束前读取。
  手动停止能取消三个并行请求并保存已收到的部分回答；全清阻断全部迟到写入。
- A 账号两题阻塞时可启动 B 账号两题，模拟上游确实同时收到 4 次请求，且各自使用正确账号身份。
  同账号重复启动被拒绝，过期批次的停止操作被拒绝；停止/清理 A 不取消 B，B 可正常保存结果。
  全清取消所有账号并删除结果。无目标的旧版 stop 配置仍能校验和应用，执行时明确拒绝，避免误停。
- 同一固定文字题，连续 2 批 × 3 轮：模拟上游分别返回不同文字、相同文字两种情况，
  均确实发出 6 个独立请求及唯一会话标识。逐条从 KV 读取后，文字和各轮 response_id 均与上游对应。
  未通过改变题目、注入随机文字或设置采样参数来制造差异。
- 单题默认 30 分钟，校验生成的请求 Context 截止时间；显式 0 不设总时长截止但仍响应取消，
  1 / 120 分钟边界有效，负数及超过 120 分钟被拒绝。旧版缺少该配置的命令规范化为 30 分钟。
- 捕获模拟上游收到的 HTTP 请求，确认所选 OAuth Token、Codex User-Agent、originator、version、
  ChatGPT 账号头及 OpenAI-Beta 与宿主解析的身份一致。该验证不代表运行了真实 Codex 客户端。
- 单题 429 后记录错误并继续。SSE 完成事件、提前 EOF、错误事件、无效 JSON、
  大响应明确标记不完整；不把 `[DONE]` 单独当作成功。
- gzip 分片、超过单值容量的回答精确重组、哈希校验、实际保存字节统计。
- 每账号最新批次替换、重复命令不重复执行、清理后迟到结果不复活。
- 最终索引提交失败时拒绝覆盖该账号的未提交批次，旧批和当前回答仍可读取，重启可恢复。
- 超过 1000 个键的完整扫描与清理；清理中断后的恢复。
- 两个账号的进程恢复分别保留已提交回答，未完成项标记中断，删除孤立分片及旧批次。
- 普通转发的请求体、重复响应头、代理、取消传播、不完整响应错误，以及
  `request_sent` 防重放语义。
- 使用宿主原样 CSP 和 `sandbox="allow-scripts"` 的真实浏览器测试：
  多选、轮数、模型与档位清空、目录失败重试、快速 A→B→A 切号丢弃旧目录、
  停用后重新启用须重新选择参数、关闭弹窗后任务完成、重开查看、
  HTML 原文、SVG 动画确实改变位置、生成页面无法访问父 DOM、外部请求被阻止、全清。
- 浏览器表单默认 30 分钟、选择不限时时提交 0；运行面板同时显示三道题目、各自已用时间与时限。
- 浏览器中已有任务时继续添加其他账号、关闭重开显示两张任务卡、禁止重复启动同账号、
  分账号停止和清理、全清。一个账号结束时，即使其他账号仍运行，当前结果也能自动刷新。
  切换不同账号、同题不同轮次及返回已缓存的上一轮，文字和请求信息分别对应正确结果。
- 发布包使用 Ed25519 签名，逐文件 SHA-256，核对公钥配置、三个运行平台，

## 0.1.4 旧结果刷新修复

- 先通过浏览器夹具复现：读取第一批回答后，第二批在两次状态轮询之间开始并结束。
  模拟上游分别返回“本次上游实际回答 1”和“本次上游实际回答 2”，旧实现切回结果页后仍显示 1，
  等待新回答超时。此前仅根据 active 列表判断任务结束，漏掉从未被轮询观察到的短任务。
- 修复后将服务器 stored 中的批次 ID、状态与已加载记录核对，变化时自动读取结果，
  不依赖轮询曾看见运行中状态。回归测试在返回结果页前确认轮询已触发读取，
  最终展示回答 2，session_id 和 response_id 均与上一批不同。
- 返回结果页时也刷新已选账号；未变化的结果不会在每次状态轮询时重复下载。
  全部 10 项浏览器流程通过，包括多账号并发、结果隔离和动画预览。
- 本次未改变题目、系统指令或采样参数；修复显示旧回答不等于保证上游措辞变化。

## 0.1.3 断流恢复与动画预览修复

- 先用可控 Reader 复现：完整结束事件与 `unexpected EOF` 同时返回时被误判失败、
  `response.created` 中的响应 ID 丢失、截断事件被归类成 JSON 错误，以及事件超限提示含糊。
  修复后分别校验完成状态、响应信息保留和具体错误原因。
- 用模拟 HTTP 上游声明较大的 Content-Length 后提前关闭连接，复现真实响应体读取的
  `unexpected EOF`。第一次无内容断流后，第二次请求成功；从 KV 读回的重试记录与两个独立
  会话 ID 一一对应。持续无内容断流只发出 3 次请求。
- 已收到部分正文、推理摘要或 `output_text.done` 内容时，保留内容并标记未完成，不自动重放。
  上游明确失败、无效 JSON 事件和超过 16 MiB 的事件也只请求一次；原有 HTTP 429 测试保持通过。
- 父 Context 在重试等待期间到期时立即结束，不发出下一次请求；多账号停止与清理的已有
  取消传播、阻断迟到写入测试继续通过。
- 增量与 `output_text.done`、`content_part.done`、`output_item.done` 快照不重复拼接；
  缺少最终完成事件时仍保留快照正文和摘要。超过 32 MiB 的心跳流不再截断合法的后续回答，
  单事件与回答内容的大小限制继续有效。
- 浏览器验证鹈鹕 HTML 片段、带说明文字的代码围栏、未闭合围栏直接渲染，内联脚本确实执行；
  切到新建页面再返回恢复预览，切换原始 HTML 时逐字保持模型原文。
- 重试成功和最终失败的结果均显示尝试次数；请求信息使用实际响应对应的会话 ID，
  保留前一次断流原因，避免重试成功掩盖网络问题。

## 0.1.0 审查修复的回归验证

- **模型目录竞态**：延迟第一个 A 账号的响应，再依次选择 B、A，原实现会残留旧模型选项。
  增加目录请求版本校验；旧成功和失败响应均不能覆盖当前选择。
- **停用后的过期状态**：插件停止时原弹窗仍保留模型和档位，重启后可能提交旧参数。
  统一清除模型、档位、结果读取状态和缓存，并使未完成的读取失效。
- **最终提交失败后覆盖结果**：注入最后一次索引写入失败，原实现仍允许新任务覆盖 Pending。
  现在拒绝同账号新任务，保留可读结果，提示通过重启恢复或主动清理后再测。
- **测试脚本漏提交**：宿主根 `.gitignore` 的 `tests` 规则会忽略本插件的浏览器与验包脚本。
  只在插件自身 `.gitignore` 中添加例外，并确认两份脚本出现在可提交文件列表中。

前三项均先用新增回归测试复现失败，再验证修复后通过。普通转发、后台运行、清理与
重启恢复的已有测试也全部通过；公开 SDK 快照与宿主原文件逐字节一致。

## 重现

在插件根目录执行：

```sh
go mod tidy
go vet ./...
go test -race ./...
go run ./cmd/packager build
node tests/verify-package.cjs
unzip -o -q dist/gpt-inspector-0.1.4.s2plugin -d build/package-check
INSPECTOR_TEST_BINARY="$PWD/build/package-check/runtimes/darwin-arm64/gpt-inspector" go test -race -count=1 ./...
INSPECTOR_UI_DIR="$PWD/build/package-check/ui" npm test
```

根据测试机的平台调整 `INSPECTOR_TEST_BINARY`。浏览器测试截图和示例账号均来自夹具，
不是实际 GPT 账号的智力测试结果。测试浏览器使用软件渲染，避免本机 macOS 无头 GPU
截图遗漏嵌套沙箱 iframe；该选项不进入发布插件。

## 尚未验证的部署行为

本次 0.1.4 升级包尚未在用户运行中的容器实际导入/启用，也未使用真实账号复测。
因此真实账号权限、上游模型目录、代理连通性、Codex 接口运行时兼容性，以及部署中的
Redis 持久化仍需升级后确认。插件不会静默回退模型、换号重试或根据测试答案自动评分。
经用户确认，本插件提供 Codex OAuth 身份的账号直测；不承诺复现真实客户端上下文和普通网关
对请求执行的模型映射、提示词/工具改写、会话指纹处理。

针对用户报告的“同一道文字题多轮回答完全相同”，已在用户授权的 Chrome 中查看实际部署的
0.1.3 页面：最新批次创建于 2026-09-24 23:39:50，每题 1 轮，模型 gpt-6-sol、强度 max。
日本首相题显示“知识截止到 2024 年 6 月、岸田文雄”及对应的 session_id、response_id。
读取时上一批已被最新批次替换，无法再取得两批完整响应作比较。因此不能将已复现的刷新缺陷
认定为该真实样本重复作答的原因，也不能确定是上游重复生成。
固定输入可能产生相同回答，新会话标识不保证措辞变化；真实 Codex 客户端的系统指令和上下文
也与账号直测不同。再次核对时应在同一批次选择同一文字题并设置多轮，以同时保留各轮证据。

用户反馈的“等待后无回答并报响应流中断或事件过大”只有旧版合并后的错误文本，无法唯一确定
是哪个网络环节中断或是否触发大小限制。新版补充了错误分类和有限重试，需在实际账号通道
复测；持续上游/代理故障可能仍然失败，此时各次尝试的错误会明确保存。
